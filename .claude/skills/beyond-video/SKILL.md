# Beyond Video

Read `STYLE.md` before anything else; its rules are non-negotiable.
Each step ends by waiting for the user. Small steps, one at a time.

## 1. Script first
Write the script. Offer 3 opening hooks:
- A — a question
- B — a contrast
- C — a dramatized scene

The user picks one and refines it ("rewrite hook B, make it shorter"). Don't move on until the script is approved.

## 2. Storyboard, second by second
On "write the storyboard", create `TREATMENT.md`. One entry per scene:
- **ID + time range** — e.g. `S8 · 44.2–50.2s`
- **Shot** — wide or close-up
- **On-screen text**
- **Position** on screen
- **Sound**

Last scene is always the closing logo + CTA.

## 3. Code: every frame is a function of time t
`frame = f(t)`. Everything animates from `useCurrentFrame()`. No timers, no `Math.random()` (use Remotion's seeded `random(seed)`), no CSS transitions or animations, no state carried between frames. Same frame → same pixels, so Remotion Studio and the rendered MP4 match frame for frame.

Remotion (React), one project at the repo root, one folder per video, shared code in `lib/`:
- `lib/` holds everything videos share: `core.ts` (timing helpers, `makeCues`, camera, easing), `palette.ts` (the app's tokens and fonts), `Fx.tsx`, `Phone.tsx`, `Logo.tsx`, icons, `Sticker.tsx`, `Backdrop.tsx`, `Home.tsx` (the app's Home redrawn).
- `src/Root.tsx` registers each video as a `<Composition>` (1080×1920, 60fps).
- `<video>/Film.tsx` holds the scene timeline and imports `scenes/S01.tsx…` — one file per scene, keyed to the TREATMENT.md IDs. Each scene exports `Scene`, its `sfx` cues and optionally `camera`. `<video>/voice.ts` binds the video's manifest: `export const {VOICE, cue, voiceEnd} = makeCues(manifest)`; scenes import `cue`/`voiceEnd` from `../voice`.
- Sound effects are generated by `npm run sfx` into `public/sfx/`; no downloaded audio. Voice clips live in `public/vo/<video>/`.
- Preview: `npm run studio`. Stills: `npm run still -- <video> <out.png> --frame=N`. Render: `npm run render -- <video>` → `out/<video>.mp4`. Voice: `npm run tts -- <video> [--standin]`.
- Build a few scenes, get the look approved, then the rest.

## 4. Voice
Default: generated. The script lives in `<video>/voice.json` as per-scene **segments** (split where a cue must land: a sentence, a list item), with per-segment pauses and per-scene lead/tail. `npm run tts` (`scripts/tts.mjs`) generates with Gemini TTS (`GEMINI_API_KEY` in `.env`; the Mac's Indonesian voice stands in for anything Gemini could not do), one request per group of same-style scenes with segments joined by `<long pause>`, cuts the audio at those pauses (text-length-aligned), assembles each scene clip with its own pauses, applies one constant gain to −14 LUFS, and publishes clips + `public/vo/manifest.json` together. Free tier: 3 requests a minute; the script paces itself and honours the server's retry delay. Cached per scene, so a script edit regenerates only its group. Scenes take their timing from it with `cue(id, segment, fraction)` and `voiceEnd(id)` from `core.ts`; never hard-code a frame that belongs to a word. Regenerating the voice re-syncs everything.
Emphasis: CAPITALS on the key word of each sentence, `<short pause>`/`<long pause>` tags, a per-segment `style` (e.g. list items: "keep the tone rising"). To speak with the user's own voice: record Google's consent sentence as `public/consent.m4a`, then `npm run voice:clone` (`scripts/voice-clone.mjs`) replicates the voice from `public/vo.m4a` and writes the `voice_…` id into `voice.json`.

Alternative: the user records one take. `npm run vo` (`scripts/vo.mjs`) cleans it (denoise from the lead-in room tone, gentle gate, mute pauses ≥ 0.35 s, one constant gain); the scene ranges then have to be measured by silence detection. Check audio by numbers, not by ear: 10 ms peak envelopes around a pause must show silence in the pause and the next word's onset intact.

Sound effects go through one `SFX_GAIN` knob in `Film.tsx` and should sit ~8–12 dB under the voice.

Motion: shared assets live in `<video>/Fx.tsx` (scan beam, flow beads, flying chip, ring, scramble). Every animation must explain something (money moving, text being read, data travelling); holds longer than ~2 s need a beat. Each scene may `export const camera: CameraKey[]` (frame, zoom, focus x/y, duration): the shell eases between keys, so the camera zooms into what the voice names and pulls back for the wide view. Keys must not overlap in time.

## 5. Check, render, commit
- The user watches the preview and gives feedback by scene number ("S5: the sea in front shouldn't cover the hatch"). Fix only what was named. Expect several versions (v1 → v3).
- `npm run render` renders every frame to a 1080×1920, 60fps MP4 in `out/` — **only when the user asks**.
- `git commit` as a checkpoint — **only when the user asks**.

Five rules: read first, give context, give small instructions, test, commit.
